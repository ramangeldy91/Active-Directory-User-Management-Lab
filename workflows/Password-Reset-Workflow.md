\# Password Reset Workflow



\## 1. Purpose



This workflow defines a secure and auditable process for resetting an employee's password in Microsoft Entra ID.



The objective is to restore legitimate user access while protecting the account from unauthorized password changes.



\## 2. Scenario



\*\*Request Type:\*\* Password Reset

\*\*Test Account:\*\* Password Reset Test User 01

\*\*Employee ID:\*\* LAB-USER-004

\*\*Environment:\*\* Microsoft Entra ID (cloud-only test tenant)



A user requires a password reset because they cannot access their account or have forgotten their current password.



\## 3. Standard Operational Workflow



\### Step 1 - Receive and Verify the Request



\- Receive the password reset request through an approved support channel.

\- Verify the requester's identity using the organization's approved identity verification procedure.

\- Confirm that the requester is authorized to request the reset.

\- Never ask the user to disclose their current password.



\### Step 2 - Check the User Account



\- Locate the correct user account in Microsoft Entra ID.

\- Verify the user's identity using available account attributes.

\- Confirm that the account is enabled.

\- Check whether the request requires additional authorization under organizational policy.



\### Step 3 - Reset the Password



\- Use the authorized administrative action to reset the user's password.

\- Generate a temporary password.

\- Require the user to change the password at the next sign-in.

\- Do not store the temporary password in tickets, screenshots, documentation, or source control.



\### Step 4 - Communicate the Temporary Password



\- Deliver the temporary password through an approved secure communication channel.

\- Do not send it through an unverified email address or disclose it to an unauthorized person.

\- Instruct the user to change the temporary password immediately after signing in.



\### Step 5 - Validate and Document



\- Review Microsoft Entra ID audit logs.

\- Confirm that the password reset operation completed successfully.

\- Record the outcome without recording the temporary password.

\- Update and close the support request according to organizational procedures.

\## 5. Security Considerations



\- Identity verification must take place before a password reset.

\- Password reset privileges must be restricted according to the principle of least privilege.

\- Temporary passwords must be transmitted securely.

\- Temporary passwords must never be included in evidence or source control.

\- Password reset operations should be auditable.



\## 6. Lab Limitations



\- The lab uses a cloud-only Microsoft Entra ID test tenant.

\- No real employee identity verification or manager approval was performed.

\- The temporary password was generated by the portal, but an end-user sign-in and subsequent password change were not independently tested.

\- No production help desk ticketing or secure password delivery system was integrated.



The successful administrative reset and its audit event were verified. This does not establish that the test user successfully authenticated with the temporary password.
